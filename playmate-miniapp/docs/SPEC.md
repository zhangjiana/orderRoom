# 一起玩：微信小程序首版

## 目标与已确认范围
根据本任务已讨论并继续确认的方案，实现家长端微信小程序：附近约玩、发布、报名、取消、我的约玩、再次约玩。默认 4～8 岁、家长陪同、公共场所。
本次为本地可运行体验版，示例家庭明确标注为演示；不声称实现真实匹配。城市未确定，不读取精确位置。后续上线须接入身份、共享数据库、审核、通知以及双方同意的玩伴关系。

## 技术与目录
原生 JavaScript / WXML / WXSS，无运行时依赖。pages 为页面，utils 为存储和业务规则，tests 为 Node 内置测试，docs 为需求说明。

## 命令
测试：cd playmate-miniapp && node --test tests/*.test.js
开发：微信开发者工具导入 playmate-miniapp，使用测试号或填写自己的 AppID，普通编译。

## 代码风格
CommonJS，双空格缩进；业务规则独立于页面；示例：`const activity = store.getActivity(id);`。页面仅转换输入、调用业务规则、呈现结果。

## 验收
- 首页筛选年龄与活动类型，空结果可发起约玩。
- 详情展示时间、公共地点、人数和家长陪同；报名须确认陪同、满足年龄，不能重复或超额报名。
- 发布校验必填、未来时间、最低人数和容量。本人自动计入。
- 达最低人数显示已成行，退出后重新计算；截止不足人数标记未成行；开始后不能报名，结束后可再次发起。
- 数据本地保存，重启仍保留；写入失败需告知，不能显示假成功。
- 玩伴页展示本地意愿，不虚构对方同意；真实互选留待后端阶段。

## 测试
Node 测试状态转移、重复报名、满员、时间边界、输入验证及持久化；微信工具可用时编译并检查页面，否则明确说明未经微信端验证。

## 边界
始终：输入校验、演示标记、最小化儿童信息。禁止：收集照片/真实姓名/住址、修改现有餐饮项目、公开发布或上传代码。实际上线所需 AppID 和后端部署参数后续由用户提供。

## 实施顺序
1. 配置及业务状态模型，测试边界。
2. 首页、详情、发布和个人约玩组成闭环。
3. 家庭资料、玩伴意愿、使用说明和整体验证。
